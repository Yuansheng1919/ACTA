# 直连文本协议（M2）

以 `ACTA_RUNNER=direct` 选择直连。配置 `ACTA_DIRECT_URL`（完整 Chat Completions 端点）、`ACTA_DIRECT_MODEL`、`PROVIDER_KEY` 和可选的 `ACTA_DIRECT_TIMEOUT_MS`。地址、模型和密钥在 listen 前校验。生产端点使用 HTTPS；本机假供应商接受回环 HTTP。

每个获准且需要生成的请求发送一次 POST。请求体仅有 model、stream=false、messages。系统消息由 Engine 提供，用户消息包含序列化任务数据。没有 tools 或工具消息。取首项 assistant.content，校验正常结束标记和完整产物。超时、连接错误、非 200、重定向、refusal、content_filter、意外工具调用及内容不合格都终止；直连建卡也不二次修稿。重放、鉴权失败和本地输入拒绝的派发次数为 0。

下游 stream=true 仍收全上游、校验正文与状态、提交后才发 SSE。job_dispatch 保存派发尝试，job_attempt 记录单次结果和可确认的 input_tokens/output_tokens。job_finish/job_failed 汇总 attempts、upstream_calls、tool_roundtrips 和 host_invocations。直连获准生成对应 1/1/0/0；重放对应 0/0/0/0。host 内部实际的上游调用和工具往返无法从宿主契约观测，调用 host 时这两项记 null。失败的派发数不等于供应商已收到或计费的次数。

`node --test test/direct.test.mjs` 使用独立本地假供应商，核对请求体、实际 POST 数、断流/超时、终态拒绝及无回退。在上游只发送半截响应时直接监听 Engine，核对闸门前响应头未到达、正文字节为 0。真实供应商的模型行为、费用、TLS 链路和 10 对 A/B 未验证。
