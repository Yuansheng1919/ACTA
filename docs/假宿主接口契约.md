# 假宿主接口契约（脱敏 · 供上游对接用）

> 这是现有"模型宿主路径"的**进程级契约**，去掉了一切内部标识。上游按此写 mock 或适配器即可离线跑通。
> 配套可运行 mock：本目录 `fake-host.mjs`（零依赖，Node ≥ 18，ESM）。

---

## 一、为什么有这个契约

现有实现里，"跑一轮"= 起一个外部宿主进程，把任务文本喂给它，它按约定把产物写进作业目录。
**这段是唯一与具体宿主强耦合的地方**；把它抽成契约，上游就能用 mock 完全离线开发，不必接触真实供应商。

---

## 二、进程契约

```
spawn(node, [HOST_ENTRY, PROFILE, "-"], { cwd: JOB_DIR, env: ENV, shell: false })
       │                │         │
       │                │         └─ 单字符 "-" = 任务从 stdin 读
       │                └─ profile 名（本项目的档位标识）
       └─ 宿主入口脚本
```

| 项 | 约定 |
|---|---|
| `cwd` | **本轮作业目录**；宿主只允许读写自己的 cwd |
| `stdin` | UTF-8 任务文本，写完即 EOF（不交互、不期望多轮） |
| `stdout` | 只作诊断；**不作为正文来源** |
| `stderr` | 只作诊断；用于定位上游拒绝/超时 |
| 产物 | `out/part-001.md`（可 `part-002.md`…；按序号顺序拼接） |
| 退出码 | `0` = 正常结束（**不等于成功**，成功以产物为准）；非 0 = 失败 |
| 生命周期 | **一进程一轮**：任务喂完 → 进程退出 → 下一轮起新进程。**禁止复用同一进程/会话** |
| 预热 | 允许先起进程、stdin 暂不喂（宿主须在读到 stdin 前完成自身初始化） |
| 超时 | 由调用方计时并强杀（建议默认 480 秒） |

## 三、环境变量（语义化，不含真实值）

| 变量 | 含义 |
|---|---|
| `HOME_ROOT` | 宿主的运行根（会话/缓存），由调用方指定 |
| `PROFILE` | 档位名 |
| `PROVIDER_KEY` | 供应商凭据；**只在进程环境里，不落文件、不进日志** |
| `NO_PROXY` / `no_proxy` | 追加直连白名单（内部网关不走代理） |

## 四、产物判据（调用方侧，不依赖宿主自述）

```
1. out/ 下存在至少一个 part-*.md，且首个非空
2. 每个分片 mtime ≥ 本轮开始时间（防陈旧文件冒充）
3. 分片按序号拼接后非空
```

**不要求**宿主写任何"完成标记文件"——判据只看产物。

## 五、失败分类（调用方据此决定重试与否）

| 现象 | 分类 | 处理 |
|---|---|---|
| 退出 0 但无产物 | 空回 | 不自动重试 |
| stderr 含鉴权/余额字样 | 上游不可用 | 不重试，直接报错 |
| stderr 含超时/连接字样 | 传输故障 | 交给上层策略（本项目：不自动重试） |
| 产物存在但校验不过 | 内容不合格 | 由闸门决定（本项目：最多重写一次） |

> **本项目铁律：付费调用永不自旋。** 一次动作一次调用，失败即停并记录。

## 六、离线自测（用本目录 mock）

```bash
cd <一个空目录>
mkdir -p out
printf '任意任务文本' | node <path>/fake-host.mjs <profile> -
# 期望：out/part-001.md 生成，退出码 0，stdout 只有一个句点
```

mock 支持故障注入（用于测闸门）：

```bash
HOST_MODE=empty  node fake-host.mjs <profile> -   # 不写产物
HOST_MODE=refuse node fake-host.mjs <profile> -   # stderr 报策略拒绝
HOST_MODE=slow   node fake-host.mjs <profile> -   # 睡 3 秒再写
```

## 七、直连路径（目标形态）与宿主契约的关系

直连路径**不 spawn 进程**：一次 HTTPS 就是一轮。两条路径对上层暴露同一个内部接口：

```
runTurn({ jobDir, taskText, signal }) → { code, stderr, stdout, ms }
```

因此上游只需实现两个 `runner`，其余模块（装配、闸门、打包、会话、日志）与 runner 无关。

## 八、需要上游回执的三件事

1. mock 跑通后，是否认可"退出码 0 ≠ 成功，成功只看产物"这一判据
2. 预热语义（先起进程、后喂 stdin）在你们的适配器里是否保留
3. 直连路径下，`runTurn` 的返回结构是否够用（是否需要"上游实际尝试次数"字段）
