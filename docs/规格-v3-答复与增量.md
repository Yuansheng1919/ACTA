## 一、开工前那三件事，我们的答案

上游指出"谁拥有会话状态、一轮何时算提交、导出卡脱离 Engine 后能提供什么"必须先写清。答复如下：

### 1.1 会话状态归 Engine（接受）

- Engine 是**唯一写入方**；客户端只持有 `session_id` 与 `expected_rev`
- 一张卡可开多局；**一局只有一个已提交的状态版本**
- 新增 `POST /v1/sessions {card_revision}` → `{session_id, state_rev}`
- 有状态请求携带 `session_id`、`turn_id`、`expected_rev`
- 冲突（同键异参、旧版本新请求）→ **409**，不静默改写
- 重放窗口内同键同输入 → 返回原结果，**不增加上游调用**
- 单机单写者；提交记录用"临时文件 + 原子替换"，重启后可区分已提交 / 未提交

### 1.2 一轮何时算提交（接受"收全 → 校验 → 提交 → 再返回"）

```
收全本轮正文 → 校验正文与候选状态 → 写提交记录（新状态 + state_rev） → 才允许向客户端输出正文
```

- **闸门未过不发任何正文**，失败走普通 HTTP 错误
- 代价：首个可见正文要等整轮完成。M3 分三段计时：上游首块 / 用户首个正文字节 / 整轮完成
- SSE 仍是流式，但流的起点在闸门之后

### 1.3 导出卡脱离 Engine 后能提供什么（接受"只承诺便携能力"）

- 卡写入三个版本戳：**卡修订号 / 状态 schema 版本 / guard 版本**（放命名空间扩展）
- 导出说明里逐项列出：脱离 Engine 可用的字段、世界书条目、以及**不可用的能力**（如服务端结算、会话续接）
- 存量无版本戳的卡：仅当来源与格式可唯一映射时才绑旧版，否则按"便携文本卡"导入

## 二、原稿四问：逐条答复

| 上游裁决 | 我们的处理 |
|---|---|
| **配额后置，但 M0 加每 IP 短时限速；以独立 token 为单位** | **接受，进 M0**。鉴权后、调上游前**预占**额度与并发位；一个 token 可独立撤销；IP 只用于削峰；代理只采信已配置的上一级；重启后恢复当天用量 |
| **守卫搬到服务端值得；保留一份 guard 实现；卡写版本戳；导出说明列便携能力** | **接受**。guard 只保留一份（服务端）；卡带三版本戳；导出说明按 1.3 执行 |
| **"导入后跑三轮"写进 M1，但要指明三轮由谁结算** | **接受，且分两档声明**：①裸卡导入只验文本与世界书；②Engine 路径验三轮状态。**对外的"完整游玩"声明只给第②档** |

## 三、规格增量（v2 → v3）

### 3.1 新增模块

```
engine/session.mjs    会话与状态版本：开新局 / 读当前 / 提交 / 重放 / 冲突判定
store/commit.mjs      提交记录：临时文件 + 原子替换；已提交 vs 未提交的区分
http/routes/sessions   POST /v1/sessions
```

### 3.2 校验挂到对象上（原稿"六条硬边界"改为分对象）

| 对象 | 硬失败 | 只记 warn |
|---|---|---|
| **CardSpec（输入）** | `age` 必须整数且 ≥18；地点/时段必须在配置枚举内；可游玩集合非空；命中拒绝规则 | 无（不付费重写） |
| **五段卡文案** | 逐字段：类型、非空、各自字数、禁词。字数按 **NFC 规范化后的 Unicode 码点**统计，排除空白、保留标点；每个字段用"恰好达标"与"±1 字"两组样例锁定边界 | 平均句长、明喻密度、规则触发计数 |
| **剧情正文** | 本轮字数（1,200–1,500 **是否硬范围需产品确认**）、禁词、完整性；供应商明确策略拒绝即终止该轮 | 文风指标 |
| **结构化状态** | 角色槽只允许一个目标角色；路径/类型/范围/迁移必须合法；**非法写入拒绝整轮**（不发布与状态冲突的正文） | 仅展示用、不进状态的附加元数据 |

**错误码补齐**：新增 `400`（坏 JSON/不支持参数）、`404`（不存在或不可见）、`409`（版本或幂等冲突）、`422`（合法 JSON 但规格不合格）。全部带稳定 `code` + `trace`，不回原文、不回供应商原始错误体。

### 3.3 我们接受但需要产品口径的一条

> 上游指出："自由文案绝无第二角色"没有可验证的全称判据。

**我们承认这一点，并把原稿第 1 条拆成两层：**

| 层 | 判据 | 强度 |
|---|---|---|
| 结构化角色槽 | 只允许一个目标角色 | **硬**，可机械验证 |
| 自由文案 | 命中禁用名单 / 模板（称谓、场外点名等）即拒；其余人工抽查 | **软**，不做全称保证 |

产品侧必须声明三件事，否则这条无法验收：
1. 是否允许玩家出现在示例对白里
2. 是否允许提及场外人物（如"楼下邻居"）
3. 若坚持"逐卡保证无第二角色"→ 需人工验卡，或把文案收窄到可机械验证的模板

### 3.4 直连路径的口径

- **宿主实测只作观测**，不作契约；直连走供应商公开支持的请求形状
- 策略拒绝 → 终止，**不换角色 / 不换 runner / 不换供应商重发**
- 预热池**仅在有冷启动瓶颈的宿主路径保留**（本项目实测冷启动 2.67 秒，故保留；直连不预热）
- 直连是否省掉工具往返、一次请求实际几次上游尝试：**由计数器回答**，不写进设计假设

### 3.5 鉴权与入口（接受"Basic 与 Bearer 不能叠加在同一路径"）

```
业务 API    TLS + 应用 token（单一 Authorization: Bearer）
管理端      只绑定本机，不对外映射；调试页若需 Basic，单独路径
代理        只采信已配置的上一级地址
```

### 3.6 出包与发布（接受"临时写 + 回读 + 发布指针"）

- 先在临时目录写完整套，**独立回读校验**，再用**单一发布指针**暴露
- 返回体给出 `bundle` / `manifest` / 可取回位置；下载的是**同一修订**
- 卡内嵌世界书与独立 JSON **从同一源生成**
- 双块分别解码校验（CRC、格式标记、各自 schema），五段文本与可映射条目逐一比对；V2 回填允许规范要求的差异
- ZIP 摘要放发布记录，**不放进文件自身**

### 3.7 日志与争议核对（接受）

每次尝试记录：`trace / job_id / attempt / 阶段 / runner / 模型标识 / 卡修订 / guard·schema·规则版本 / 失败规则号与字段路径 / 期望范围与实测值 / state_rev 前后 / 耗时 / 用量`。

- 重写 = 同一 job 的第二次 attempt
- 供应商未返用量填 `null`（**不用 0**，避免被当成免费）
- 区分三类量：模型 token 数 / 手发密钥 / 用户每日额度
- 分别记录：队列等待、实际发出次数、可确认用量、最终交付结果
- 验收用**唯一探针字符串**检查：应用日志、代理日志、宿主 stderr、守护进程日志、错误回包
