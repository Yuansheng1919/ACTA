# M1-03 三轮结算 · 预期表（手写，不得由被测 guard 生成）

> 规则来源：上游回执 §二.1 与 §四。**预期值必须手写**——如果用被测实现自己生成预期，这项验收等于自证。
> 本表所有值为合成配置值；实现时请用等价语义替换为你自己的字段名，**预期结果不得改变**。

## 一、前置

| 项 | 取值 |
|---|---|
| 卡 | 任意通过硬边界的合成卡（`cards/A-单角色新规范.png`），卡修订号记为 `card_rev=1` |
| 状态枚举 | 时段 ∈ {`早`,`晚`}；地点 ∈ {`甲`=客厅, `乙`=她的房间} |
| 未配置值 | `丙`=未在枚举内（用于非法写入用例） |
| 结算方 | **Engine**（服务端 guard）。裸卡模式不计入本表 |
| 上游 | 真实 HTTP + 真实 guard + 真实存储，**只替换上游模型为假宿主** |

## 二、主链（必须逐格对上）

| 轮次 | 起始状态 | 固定候选事件 | 提交后预期 | 核对点 | 期望上游调用数 |
|---|---|---|---|---|---|
| 1 | `rev 0`、地点`甲`、`早` | 合法移动到 `乙` | `rev 1`、`乙`、`早` | **第二轮实际装配读到的地点 = 乙** | 1 |
| 2 | `rev 1`、`乙`、`早` | 合法进入 `晚` | `rev 2`、`乙`、`晚` | **第三轮实际装配读到的时段 = 晚** | 1 |
| 3 | `rev 2`、`乙`、`晚` | 合法移回 `甲` | `rev 3`、`甲`、`晚` | **进程重启后读回 = `rev 3`**；重放第 3 轮仍为 `rev 3` | 1（重放 +0） |

## 三、异常链（每项独立造一次）

| 编号 | 场景 | 期望观测 |
|---|---|---|
| N-1 | 第 4 轮提交**未配置地点** `丙` | 状态保持 `rev 3`、`甲`、`晚`；**正文不发布**（与状态冲突）；返回 422 或 `verdict.state_reject`；记录被丢弃的候选事件编号 |
| N-2 | 同一 `turn_id` 并发重发两次 | 只结算一次；第二个请求取回原结果；**上游调用数 +0** |
| N-3 | 同 `turn_id` 但请求体不同 | 返回 **409**；状态不变 |
| N-4 | 用旧 `expected_rev` 提交新一轮 | 返回 **409**；状态不变 |
| N-5 | 提交成功后、响应前断开连接，然后客户端重试 | 重试取回原结果；`state_rev` 不变；无第二次上游调用 |
| N-6 | 提交前上游失败（假宿主 `refuse`） | 状态保持旧版本；`state_rev` 不变；记录"已发上游、结局未知"一条可对账记录 |
| N-7 | 守卫替换为空操作（no-op） | **本表第一至三行必须全部失败**——若不失败，说明测试没接上真实 guard |

## 四、多局隔离

| 场景 | 期望 |
|---|---|
| 同一张卡开第二局（session B） | B 从 `rev 0`、初始值开始，不受 session A 的 `rev 3` 影响 |
| 两局并发写入 | 各自独立结算；互不覆盖 |

## 五、需要随回执提交的证据

1. 每轮：`session_id`、`turn_id`、`expected_rev`、提交后 `state_rev`、状态快照（脱敏）
2. 每轮：**下一轮装配实际读到的值**（证明"读回"而不是"内存里有"）
3. 重启前后的读回对比（N-3 行与主链第 3 行）
4. 上游调用计数（含重放 +0 的证明）
5. N-7 空操作 guard 的失败截图/日志——**没有这条，本项不算通过**

## 六、判定口径

- 主链 3 行任一不符 → **不通过**
- 异常链 7 项任一不符 → 不通过（其中 N-7 是必测项）
- 多局隔离不符 → 不通过
- 只支持裸卡的客户端：本表整体标注「此模式未承诺」，**不计入 Engine 三轮通过数**
