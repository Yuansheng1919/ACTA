## 实现约定及实测边界

- 第一批的角色修订为不可变私有实体。开局用 `POST /v1/sessions {card_revision}`。游玩接口支持文本和闸门后 SSE；会话参数接受 JSON 字段或 `x-session-id`、`x-turn-id`、`x-expected-rev`。调用方可用 `GET /v1/sessions/:id` 读当前状态。
- 承诺单机单写者。同一会话可重放最近 64 个终态轮次中 24 小时以内的结果。正文在会话恢复记录内可见；运行日志只留元数据与 HMAC。日配额按 UTC 日期，对生成作业一次预占，卡稿修复作为同一作业第二次尝试。内容拒绝和宿主拒绝不退已派发额度。
- 产物协议：建卡任务返回五字段 JSON。剧情可返回纯文本（无状态候选），或 `{"text":"…","events":[{"op":"move","value":"乙"}]}`。状态只能由 Engine 计算。自由文案仅对配置词表与模板作确定性判定，其他语义由本地抽查。
- 运行入口为 `npm start`。必填 `ACTA_DATA`、`ACTA_TOKEN_FILE`（调用 token 的 JSON 字符串数组，修改后下次请求生效）、`ACTA_HMAC_KEY`。隔离的本地演示可将 `ACTA_HOST_ENTRY` 指向 `acceptance/fixtures/scenario-host.mjs`。生产规则由 `ACTA_POLICY` 加载，示例规则只供合成验收。数据目录及 token 文件由单一服务账户持有。HMAC 托管与保留期仍由项目方决定。
- 反向代理实测使用本地监听的转发进程和实际网络套接字；诊断接收端是本地服务进程与测试父进程。生产 TLS、具体反代配置、系统守护日志、Windows 实机、目标第三方客户端与真实供应商尚未在本批验证。管理路径在公开监听器不可达。资源打包/导入与第二、三批能力单独验收。
